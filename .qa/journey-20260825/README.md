## 通しで**見つけた実バグ 3 件**（→ GAP-210 で修正）

単体テストでは出ず、**実際に登録したから**出たもの。

### ① 同意の記録が「読んだ版」でなく「登録した日付」だった（一番重い）

`connector.ts` の `signup()` が `new Date().toISOString().slice(0,10)` を
consent の version に入れていた。

```
登録直後の人:  terms_of_service | 2026-08-25   ← 登録日
現行の文書  :  terms_of_service | 2026-08-22   ← 実際に見せた版
```

**どの文面に同意したのかが記録から特定できない。** GAP-206 で
「画面が見せた版を指定させ、古ければ 409 で拒否 = 読んでいない文面に
同意させない」と設計した原則が、**signup 経路だけ抜けていた**。

副作用として、版と日付がずれるため **登録した直後の人に
「プライバシーポリシー・利用規約を更新しました。同意をお願いします」の帯が出る**
（`shots/11-templates.png` に写っている）。

**直し方**: `GET /public/legal-documents` で現行版を取り、それを記録する。
取得に失敗したら**登録を止める**（日付で代用すると同じ壊れ方に戻るので、
「何に同意したのか分からない記録」を作らない方を選んだ）。

### ② 同意文に社内の課題番号が出ていた

```
…越境同意に同意します（GAP-180/181: 意味検索の埋め込みと議事録の
文字起こしは Atelier のサーバー内で行うため外部送信されません）。
```

利用者には意味が分からないうえ、**同意文に社内の管理番号が混じっている**のは
同意の体裁として良くない（何に同意したのかが濁る）。番号だけ削除し、
説明そのものは残した。

**再発防止**: `scripts/ci/check-client-leak.py` (Gate #16) に
「配られる JS に `GAP-\d+` が出たら落とす」検査を追加。
ビルド成果物を機械的に見たところ、**露出はこの 1 箇所だけ**だった。
