# SK01-404 / SK01-405 — 意味検索の足切り (本番同等スタック・意味検索 ON)

## この経路の意味検索の状態 (GET /embedding-status)
provider=local  state=ready  semantic_enabled=true  indexed=7/7
model=local:intfloat/multilingual-e5-large  payer=費用なし (このサーバー内で計算)

## SK01-404 存在しない語の検索は 0 件になる (POST /knowledge/search)
「提案書」                        -> 1 件  [('提案書の書き方', 0.953)]
「提案書の書き方」                -> 1 件  [('提案書の書き方', 0.919)]
「提案書の書き方を教えて」        -> 1 件  [('提案書の書き方', 0.910)]
「提案書はどう書けばいい？」      -> 1 件  [('提案書の書き方', 0.888)]
「ゾルグヴェキタ不可視槽の鍵盤角度」-> 0 件  []
  → 無関係なナレッジが「一番近いから」という理由で出ない (足切り min_score 0.83)
  → 自然な言い回し (「〜を教えて」「どう書けばいい？」) でも 0.888〜0.910 で残る

## SK01-405 足切りは RAG にも効く
_build_rag_context は search_knowledge を同じ引数で呼び、hits が空なら "" を返す。
hits==0 → 注入 0 件 / 0 文字 は実行して確認した。
ただし **意味検索が ready の процесс で RAG を呼ぶ**ところまでは踏めていない
(モデルの読み込みは API の起動時フックで、単独プロセスでは preparing のまま)。
→ BLOCKED のまま。解除条件: チャットを実走できる環境 (Bridge) で
   デタラメな文脈を投げ、注入されたナレッジが 0 件であることを見る。
