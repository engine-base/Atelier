# GAP-207 — 使えないときはサイドバーを出さない（オンボーディング）

## きっかけ

経営者から「**オンボーディングやその他でサイドバーいらないときは表示させなくて
いいよね？ その時押されても困るしUX悪いし**」。

GAP-206 の証拠スクリーンショットに、まさにその状態が写っていた。

## 何が問題だったか

新規登録直後（ワークスペースがまだ 1 つも無い）でも、サイドバーに

- プロジェクト / AI社員 / ナレッジ / テンプレート / 承認待ち / WS設定

の 6 本を出していた。**どれもワークスペースが無いと空か、そもそも作れない画面**で、
押しても何も起きない。TopBar にも「ワークスペース」という**何も指していないピル**が
出ていた（切替先が 0 件なので押せもしない）。

つまり「まずワークスペースを 1 つ作ってください」という 1 本道の画面なのに、
**押しても行き止まりの入り口を 7 つ並べていた**。

## やったこと（どこで動くか: すべて画面側 = Vercel。API も LLM も増えない）

1. **ワークスペースが 1 件も無い間はサイドバーを出さない**
   （既存の全画面モード `hideSidebar` を再利用。新しい仕組みは足していない）
2. **中身の無いワークスペースピルを出さない** — 代わりに **ロゴ**を置いて
   ヘッダーが空にならないようにした
3. **検索・通知センターも出さない** — 探すものも承認するものもまだ存在しない
   （本人のプロフィールだけ残す）
4. **ちらつかせない** — 「前回のワークスペース」を覚えていれば `useLayoutEffect`
   （最初の描画より前）でシェルを出す。既存ユーザーの画面が一瞬消えることはない。
   覚えていない（＝新規登録直後）なら、取得が終わるまで出さない

## 実ブラウザ e2e で見つけた実バグ（この GAP の本題より重い）

**ワークスペースを作っても、再読み込みするまでサイドバーが出なかった。**

シェルは起動時に 1 回しか `/workspaces` を読んでいなかったため、最初の 1 つを
作った直後もシェルの中では「0 件」のままだった。**これは今回の変更で顕在化した
だけで、元から「作ってもワークスペース名が `…` のまま」というズレとして存在して
いた**（サイドバーが常に出ていたので気づきにくかった）。

- `notifyWorkspacesChanged()`（`atelier:workspaces-changed`）を追加
- 作成した側（S-B01）が呼び、シェルが受けて読み直す
- e2e で「作成 → その場でサイドバーが出る（再読み込み不要）」を固定した

## ついでに直した文言（同じ画面で見えた）

一度も同意していない人に、再同意の帯が「**更新しました**」と出ていた。
初回の人には事実と違うので「**への同意をお願いします**」に出し分けた
（通常は新規登録時に記録されるが、移行アカウント等で記録が無いことはあり得る）。
