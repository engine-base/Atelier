# GAP-165: フェーズ確定の判断材料と、確定後の修正の「境目」

経営者質問 (2026-08-19):
「具体的にどうそのフェーズを確定として判断して、そこからの変更や修正などは
 許容できる状態にしているんだよね？？ じゃあこれはできない、フェーズ2として
 作りましょう、という感じの境目はどうしているのか？？」

## まず現状の答え (実測で確認)

**確定後も修正はできます。** 構造はこうなっていました:

| 操作 | 確定済みフェーズの成果物に対して |
|---|---|
| 直接の書き換え・版の破棄 | **できない** (409。記録として不変) |
| AI への修正依頼 (revise) / 新版の作成 | **できる** |
| その新版がどのフェーズのものになるか | **必ず現在フェーズ** (自動でスタンプ) |

つまり**「境目」は自動で引かれます** — 確定済みのものを直すと、それは
「前フェーズの修正」ではなく**現在フェーズの新しい版**として積まれます。
確定済みの版はそのまま残るので、後から「フェーズ1 で何を出したか」も追えます。

## 足りなかったもの → 今回入れたもの

| 元々 | 今 |
|---|---|
| 確定は**人がボタンを押すだけ**で、判断材料の提示ゼロ | **確定前チェック**: 未完了の工程・完了していないタスク・未解決コメント・成果物/モック件数を**実数で提示**。判定は人が行う (AI が勝手に確定しない) |
| 何を確定したのか記録が残らない | 確定時に**「このフェーズで確定した範囲」メモ**(任意)を書け、実データ (完了工程・成果物・画面) の自動サマリーと併せてフェーズに保存 |
| 「確定＝もう直せない」と読める UI 文言 | **「確定後も修正はできます。確定済みの版は記録として残り、修正すると新しい版が次フェーズの成果物になります」**と明示 (確定ダイアログ・進行タブ・モック一覧) |
| AI は境目を知らない | 確定メモと**境目のルール**を system prompt に注入:「確定済みの版は書き換えられない。修正依頼は断らずに新版を作り、"この修正は現在フェーズの作業として記録されます" と一言添える」 |

## 証拠

API テスト `TestGap165FreezeJudgement` (3):
1. `freeze-check` が未完了工程・タスク・コメントを実数で返す
2. **確定 → 確定済み成果物へ修正依頼 → 201 で通り、新版の `delivery_phase_id` は
   次フェーズ。元の v1 はフェーズ1 のまま不変** ← 境目の構造的証明
3. AI 注入に確定メモと境目ルールが入る

Web テスト `phase-switcher` (GAP-165 分 1): 確定メニューで残作業が並び、
「確定後も修正はできます」を表示し、確定範囲メモが API に渡る。
