# GAP-179 — 自動実行 (スケジュール) を実際に動かす

経営者指摘 (2026-08-19):
> 「スケジュールの部分だけの話ってこと？？」

コードベース全体を「画面・API・テーブルはあるが実行の実体が無い」で洗い直した結果、
**利用者に嘘をついている**のは 2 箇所だった。本 GAP はそのうち大きい方 (自動実行) を直す。
もう 1 箇所 (エラー監視 Sentry が未配線) は GAP-182 で扱う。

## 直す前の実態

| 画面で選べる自動実行 | 実体 | 実際に起きていたこと |
|---|---|---|
| 日次ダイジェスト | あり | 動くが **利用者の指定時刻は無視**され、固定 22:00 UTC で配信 |
| タスク再生 | **なし** | 行が保存されるだけ。永久に発火しない |
| ナレッジ整理 | **なし** | 同上 |
| 業界パターン抽出 | **なし** | 同上 |
| 進捗レポート配信 | **なし** | 同上 |
| 週次バーンダウン | skeleton | `logger.info("...(skeleton)")` を出して終わり |

加えて:
- `next_run_at` を計算するコードが存在せず、DB 実測で **10 行中 0 行**が算出済み。画面の「次回」は常に空欄
- 画面に **「BYOK API 使用」× 4** と表示。API キーは使わない設計 (GAP-175) なので費用表示も嘘

## 直したあと

- `services/cron/expression.py` — 5 フィールド cron を **日本時間で**解釈して次回時刻を算出 (外部依存なし)
- `services/cron/dispatcher.py` — 毎分 `next_run_at <= now()` の行を実行 → 次回時刻を再計算
- `services/cron/actions.py` — **6 種類すべてに実体**。各種類が「PC 接続が要るか」「誰の費用か」を宣言
- `services/cron/burndown.py` — 週次バーンダウンの実体 (残タスク / 直近 7 日の消化 / 完了見込み)
- 固定 cron の `daily-digest` / `weekly-burndown` を **廃止**。固定時刻が先に配信すると利用者の指定時刻が
  また無視されるため、配信経路を `user-schedules` 1 本にした
- `GET /cron-actions` を追加。画面の説明・コスト表示は**実行コードと同じ定義**を読む
- PC 未接続は `deferred` (保留) として記録し **約 10 分後に自動再試行**。`error` とも `success` とも書かない

## 証拠

- `e2e-dispatcher.log` — 実 PostgreSQL に対する実行ログ (下記 5 項目)
  1. 「毎朝 9 時」で作成 → `next_run_at` が **JST 09:00** に確定
  2. 不正な cron 式 (`0 99 * * *`) は保存を拒否 (「時は 0〜23 で指定してください」)
  3. 発火時刻を過ぎたら実際に走り、ダイジェストが投稿され、次回が翌 09:00 JST へ繰り上がる
  4. PC 未接続 → `status=deferred` / `reason=bridge_offline` / 約 10 分後に再試行予定
  5. 6 種類すべての実体と費用表示の一覧
- `apps/api/tests/test_cron_execution.py` — 実 PG での 12 テスト
- `apps/api/tests/services/test_cron_expression.py` — cron 解釈 26 テスト
- `apps/web/tests/bundle-i/gap179-cron-actions.test.tsx` — 画面のコスト表示が API 由来である 5 テスト

## どこで動くか / 誰の費用か

| 自動実行 | どこで動くか | 誰の費用 |
|---|---|---|
| 日次ダイジェスト / 週次バーンダウン / 業界パターン抽出 | Fly.io の API (SQL 集計のみ) | **無料** (AI を使わない) |
| タスク再生 | 投入は Fly.io、実行は**利用者の PC の Claude Code** | 利用者の Claude プラン枠 |
| ナレッジ整理 / 進捗レポート配信 | **利用者の PC の Claude Code** (未接続なら保留→再試行) | 利用者の Claude プラン枠 |

API キーによる課金は一切発生しない (GAP-175 の既定を維持)。
