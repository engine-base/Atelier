# GAP-180 — 意味検索 (埋め込み) を「今は使わないが、いつでも設置できる」状態に

経営者指示 (2026-08-19):
> 「これはローカルはインストールが必要なやつってこと？？ちゃんとそこのフローや初期設定や
>  もし接続できていない場合の再接続のフローはできているの？？しかも Voyage は使わない形に
>  したので基本ローカルで、ただ今後使う場合があるかもしれないので**今は全く使えない状態だけど
>  設置は今後できる状態には**しておいて」「ここも完璧にやって」

## 直す前の実態

1. **`VOYAGE_API_KEY` が環境変数に「あるだけ」で Voyage が使われる**作りだった。
   GAP-178 で LLM 側は「env を消さないと使われる」設計をやめたのに、埋め込みだけ同じ問題が残っていた。
   Voyage は従量課金 (運営負担) で、しかもナレッジ本文が外部へ送信される。
2. 意味検索が使えないときの表示が、検索した後に小さく出る
   「意味検索は無効です。ローカル埋め込みの導入または **VOYAGE_API_KEY の設定**で有効になります」だけ。
   利用者に環境変数名を見せており、**理由も準備状況も復旧手段も無かった**。
3. 準備 (モデル DL) の進み具合を確認する手段が無く、「精度が落ちた」ようにしか見えなかった。

## 直したあと

- `src/embeddings/route.py` — 埋め込み経路を 1 箇所で決める。**Voyage は `ATELIER_ALLOW_VOYAGE=1` を
  明示したときだけ**使う (キーがあるだけでは絶対に使わない)。削除はしていないので、将来使うときは
  env を 1 つ足すだけで戻せる。
- `GET /embedding-status` — いま何で動いているか / 誰の費用か / 準備の進み具合 (埋め込み済み件数) /
  やること を返す。`POST /embedding-status/prepare` で準備の開始・再試行ができる (冪等)。
- 画面 (ナレッジ S-K01) に「意味検索の状態」カードを常設。準備中・利用不可なら理由と手順、
  「今すぐ準備する / 再試行する」ボタンを出す。状態が取れないときは**推測で書かず何も出さない**。
- 運営ヘルスチェックに「意味検索 (埋め込み) の経路」行を追加 (費用の出どころつき)。
- 起動ログに 1 行出す (`atelier.embedding_route`)。警告があれば warning レベル。
- `.env.example` / `SECRETS.md` を実態に合わせて書き直し。

## 証拠

- `e2e-embedding-route.log` — 実測。特に:
  - キーだけ入れた場合 → `provider=local` のまま + 警告「明示 opt-in が無いため使用しません (課金しません)」
  - 明示 opt-in + キー → `provider=voyage` (将来の設置が動くことの確認)
  - opt-in だけでキーが無い → 警告つきでローカルにフォールバック
  - ローカルを止めた → `unavailable` + 戻し方

## どこで動くか / 誰の費用か

| 経路 | どこで動くか | 誰の費用 | 既定 |
|---|---|---|---|
| ローカル埋め込み (fastembed / ONNX) | Fly.io の API プロセス内 | **無料** (外部送信なし) | ✅ これ |
| Voyage AI | 外部 SaaS (本文を送信) | 運営の従量課金 | ❌ `ATELIER_ALLOW_VOYAGE=1` を明示したときだけ |
| どちらも不可 | — | 無料 | キーワード一致検索に誠実 degrade (画面に理由を出す) |
