# GAP-151: 進行タブ = 工程ごとの会話 (stage 専用スレッド + 社員固定 + 自動オープン)

## 経営者すり合わせ (回答そのまま)

「チャットの機能は全く同じ形で使える状態にしたいけど、チャットというタブでは
なくちゃんと工程ごとに備わっている的なイメージ」「スレッドは格下げというより
各工程の中にある感じ。社員は固定的でこっちで決めておくほうがいい」

## 実装

1. **工程 = 会話の入れ物** (gap-151 migration): project_flow_stages.thread_id —
   各工程が専用の chat_thread を 1 本持つ。チャット機能 (SSE/PC 操作/添付/
   メンション/成果物カード等) は完全に同一 — 入れ物が工程になっただけ。
2. **担当社員は固定**: 工程 × 部門の代表社員 (運営テンプレの is_default) で
   サーバーが解決 — ユーザーは選ばない。部門に社員が居なければ 409 で誠実表示。
3. **ensure_stage_thread** (POST /projects/{id}/flow/{stage}/thread):
   工程を開くと専用スレッドを取得/作成して工程に固定。既存プロジェクトの
   継続性のため、担当社員の未割当スレッドがあれば採用 (会話が分断しない)。
   同部門の 2 工程目は新規 (工程ごとに別の会話)。
4. **UI**: ナビ「チャット」→「進行」。開くと**現在工程の会話が自動で開く**
   (未選択時に一度だけ)。左ペインは進行フローが主役 (✓/●/○ + 担当名 +
   完了/スキップ/差し戻し)、既存のスレッド一覧は「その他の会話」アコーディオン
   (既定閉) に収容。

## 実ブラウザ証跡 (stage-chat.png)

/chat をスレッド未指定で開く → ナビ/パンくず「進行」、左 = 進行フローのみ、
**現在工程「要件定義」の会話が自動で開き**、担当スティーブ (固定) との
チャット入力欄が使える状態。「その他の会話」は閉じたアコーディオン。
