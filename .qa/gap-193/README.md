# GAP-193 — 取りこぼした自動実行を「黙って消さない」

経営者質問:
> 「これは何？？ 日次ダイジェストの遡り生成」

## これが何だったのか

自動実行の見張り役（利用者の PC / クラウド）は、**発火時刻を過ぎた行を拾って
1 回だけ実行し、次回時刻を「今から見た次の定刻」へ進め**ます。

つまり **PC を 3 日止めていた場合**:

```
8/17 09:00 の定刻 ──┐
8/18 09:00 の定刻 ──┼─ PC が止まっていた
8/19 09:00 の定刻 ──┘
8/19 10:00 PC 起動 → 1 回だけ実行、次回は 8/20 09:00 へ
```

**間の 2 日分は実行されず、しかもログにも残らないので人が気づけませんでした。**
「遡り生成」とは「この消えた 2 日分を作り直すか」という保留中の判断でした。

## 調べて分かったこと — 遡り生成は今の作りでは正しく動かない

集計の SQL が **現在時刻に固定**されています:

```sql
-- daily_digest
and te.started_at >= now() - interval '24 hours'
-- weekly_burndown
and te.completed_at >= now() - interval '7 days'
```

さらに `_has_digest_today()` が「今日すでに投稿済みなら作らない」で弾きます。

**つまり 3 回走らせても「同じ今日の内容」が 3 個できるだけで、3 日分にはなりません。**
本当に遡るには、6 種すべての runner が「いつ時点で集計するか」を受け取れる必要が
あり、集計 SQL の作り替えになります。

→ **動かないスイッチは出しませんでした。**

## 直したこと — まず「消えたことが分かる」ようにする

1. `missed_occurrences()` を追加 — 定刻を何回過ぎたかを数える（上限 32 回で打ち切り。
   1 か月止めていても数え上げで固まらない）
2. `cron_run_history.skipped_occurrences` に**必ず記録**する
3. 画面の実行履歴に **「2 回分を未実行」** バッジを出す。
   ホバーで「その分は実行されていません（遡っての作成は行いません）」と明示

**実行されるのは今まで通り最新の 1 回だけ**です。変えたのは「黙って消える」を
「消えたことが分かる」にした点です。

## 証拠

`apps/api/tests/test_cron_execution.py`（実 PG）:

- 通常の実行は `skipped_occurrences = 0`
- **3 日止めた後の起動 → 実行は 1 回・未実行 2 回が履歴に残る**
- 復帰後は次回時刻が未来に揃う（過去に張り付いて毎分走り続けない）

`apps/api/tests/test_deploy_and_catchup.py`:
毎日 / 毎週の式で取りこぼし回数が正しいこと、未来の予定は取りこぼしでないこと、
長期停止でも上限で打ち切られることを固定。

## ⚠️ 経営者判断が必要な残件

**「遡って作り直す」をやるかどうか**は依然として判断待ちです。やる場合は
6 種の runner と集計 SQL に「いつ時点で集計するか」を通す作業になります
（GAP-196 として起票）。

個人的な所感としては、3 日前のダイジェストを今さら作っても読まれない可能性が高く、
**「何回分飛んだかが分かる」だけで足りる**ケースが多いと思います。
