# GAP-191 — 実行中のターンへ指示を直接差し込む（常駐プロセス）

## 何が足りなかったか

GAP-190 で `--session-id` / `--resume` により会話は続くようになったが、
**ターンごとに新しい `claude -p` を起動**していた。そのため
- 実行中のターンへ指示を差し込めない（GAP-189 の「終わったら次に流す」方式）
- 毎ターン起動コスト（数秒）がかかる

Claude Code のインタラクティブでは、作業中に入力すればそのまま届く。
**同じ体験にする**のがこの GAP。

## 実 CLI で確かめた事実（推測ではない）

`--input-format stream-json` で起動したプロセスは stdin を開いたまま複数ターンを
処理する。さらに **1 通目の実行中に送った 2 通目も受け取る**。

```
[2] 1 通目の実行中に 2 通目を送る（終わるのを待たない）
  OK   2 通目を送れた (t=2673ms / 1 通目の出力開始 t=2651ms)
  OK   送った時点で 1 通目はまだ実行中だった (完了 result 数=0)
[3] 2 つの result
  result #1 (t=2681ms): 1 2 3 ... 12 COUNT-DONE
  result #2 (t=4055ms): ADDED-OK
  OK   同じプロセスのまま (pid=13990)
  OK   同じ session_id のまま (ad846b31-...)
  OK   result のあともプロセスが生きている
```

## 作ったもの

### Bridge（利用者の PC）

`apps/bridge/src/persistent-session.ts`
- **スレッド（セッション）ごとに 1 プロセス**を保つ。キーは
  `作業フォルダ + セッション ID`（別スレッドの会話が混ざらない）
- `send()` は**実行中でも通る**。送れなかったら `false` を返す（送ったつもりを作らない）
- **使われなければ自分で畳む**（既定 15 分・`ATELIER_BRIDGE_PERSISTENT_IDLE_MS`）。
  利用者の PC に居座らない
- 中断は SIGTERM → 2 秒後 SIGKILL で**実際に止める**（GAP-189 と同じ）
- spawn 失敗（claude 不在）も受け取る。受けないと unhandled error でアプリごと落ちる

`chat-relay.ts`
- ツールあり + セッションありのジョブは常駐プロセスで走らせる
  （`off` は 1 往復の軽い経路なので従来どおり）
- **中断の見張りと同じ間隔で「追い足し」も見に行き、走っているターンへ流し込む**
- 流し込んだ内容は画面にも「（実行中に追加で伝えました）」として残す。
  **黙って会話に混ぜない** — 混ぜると「言ったのに反映されていない」に見える
- `ATELIER_BRIDGE_PERSISTENT=0` で従来動作（1 ターン 1 プロセス）に戻せる

### サーバー

`GET /chat-relay/{job_id}/follow-up`（Bridge トークン）
- 走っているジョブの待ち行列から 1 件取り出す（`for update skip locked` で二重に流れない）
- **走っていないジョブには何も返さない** — 終わった実行へ流し込まず、
  待ち行列に残したまま次のターンとして普通に流れる

## どこで動くか / 誰の費用か

常駐するのは**利用者の PC**。実行は**本人の Claude プラン**。
運営サーバーは「追い足しが来たか」を答えるだけで、費用は増えない。
むしろ毎ターンの起動が消えるぶん、体感は速くなる。

## 正直に書いておくこと

- 常駐プロセスは**その PC の中だけ**。PC を再起動すればプロセスは消えるが、
  会話は transcript（実ファイル）に残るので GAP-190 の `--resume` で続く。
- 追い足しは「今のターンの**直後**」に処理される。CLI がターンの途中で
  文章を書き換えるわけではない（Claude Code のインタラクティブと同じ挙動）。
- 常駐しているのはツールありジョブだけ。`off` モードは従来どおり。
