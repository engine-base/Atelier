# GAP-159: 出力デザインの種類整理 + 運営既定 (継承 / 上書き / 既定に戻す)

経営者指示 (2026-08-19):
- 「出力デザインに関しては 見積もり、提案書、請求書、契約書、NDA、要件定義書、
   アーキ設計書、デザイン仕様書、テスト仕様書、納品書、完了報告 で十分です」
- 「これは変更加えれる前提で、初めのデフォルトはこちらの管理側で設定している物でいい感じ？」
- 「管理側でデフォルトを決めると思うけどそこでも変更加えたり全く同じように更新や
   追加変更などできる状態になっているの？？」

→ **はい、その形にしました。**

## 1. 種類を 10 種へ整理

見積書 / 提案書 / 請求書 / 契約書 / NDA / 要件定義書 / アーキ設計書 /
デザイン仕様書 / テスト仕様書 / 納品書・完了報告
(旧 14 種のうち 議事録・機能分解書・タスク一覧・実装ドキュメントは廃止。
これらは「デザインを持たない工程」として AI への注入対象からも外れる)

## 2. 運営既定 → 各社が継承 → 上書き → いつでも既定に戻せる

| 状態 | 挙動 |
|---|---|
| 初期 | 運営が作った既定デザインを**全ワークスペースが継承** (source=platform) |
| 各社が変更 | その社の版 v1 が実効に (既定 HTML を**土台に**改訂するので一から作り直さない) |
| 既定に戻す | **削除ではなく新版として積む** (v2) — 履歴不滅の原則を維持 |

- DB: `output_design_templates.is_platform_default` (workspace_id は運営既定のとき NULL)。
  RLS は「運営既定は全テナント閲覧可・書込不可」「自社版は自社のみ」。
  運営側の書込は admin gate (403) + service セッション経由。
- AI への注入も継承する: 自社版が無ければ運営既定が system prompt に入る
  (表記は「出力デザインテンプレート: 要件定義書（運営既定）」)。

## 3. 運営管理画面 = ユーザー側と同一のスタジオ

`/admin/design-templates` (運営メニュー「既定デザイン」)。
**同じコンポーネントを mode="platform" で使用** — 作り・操作・見た目は完全に同一で、
ワンダに指示 → 既定デザインの新版が積まれる。追加・更新・改訂すべて可能。

## 併せて直した実バグ (この GAP の作業中に検出)

1. `routes/outputs` の content 配信用 service セッションが単一 `lru_cache` で
   event loop に固定されていた (asyncpg は loop を跨げない)。admin_knowledge と
   同じ **loop 毎の分離**に修正。本番は単一 loop のため挙動不変だが、テストでは
   2 ブロック目以降で死んだ loop の engine を掴む不具合だった。
2. GAP-153 のキュレーションテストが**運営横断のグローバル件数**に依存していて、
   他ワークスペースのナレッジがあると落ちた。自テナント由来の行だけを見るように
   スコープ修正 (キュー自体が運営横断なのは仕様どおり)。
