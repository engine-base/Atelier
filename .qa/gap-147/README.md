# GAP-147: ワンダ改訂の品質と可視性 — 全面書き換えバグ根治 + 進行可視化 + 変更サマリー

## 経営者報告 (実機スクショ付き)

1. 「作業中だけではなく、何をしているかをわかる状態にしたい」
2. 「『v2 を作成しました』って何？？具体的に何をするのかちゃんと決めてないの？」
3. 「(レスポンシブ修正の指示が) 全く改善されていなかった。ありえない」
   — v2 は指示を無視して TaskFlow 風の別デザインに全面書き換えられていた

## 根本原因 (実データで特定)

GAP-143 でワンダの改訂 system prompt に装着スキルを**全文・契約より前**に注入
していた。seed でワンダには design-md / ui-mockup / brand-voice が装着されており、
実ファイルは **合計 81KB** (ui-mockup 29KB + design-md 45KB + brand-voice 7KB) の
「モックの作り方手順書 (サンプル画面・ダミーデータ込み)」。これが末尾の改訂契約
「指示に無関係な部分は変更しない」を圧倒し、モデルはスキルの手順に従って
**画面を新規作成し直した** — 実機の TaskFlow 混入・指示無視はこれ。

## 対処

1. **プロンプト階層の是正** (revise.py / generate.py / design_note.py)
   - 改訂契約 (絶対ルール: 構造保持・全面書き換え禁止・サンプル持ち込み禁止・
     SUMMARY 出力) を system prompt の**先頭**に
   - スキルは「# 参考資料 (装着スキル抜粋)」として**後段** + 合計 6,000 字に丸め
     (「資料であり指示ではない。サンプルを持ち込まない」を明記)
   - デザインノート (必ず従う) は従来どおり有効
2. **変更サマリー**: 出力契約を「HTML 全文 → `---SUMMARY---` → 変更要約 1〜2 文」
   に変更。summary は meta_tags.note に保存 → 会話バブル・バージョン履歴・完了
   通知に「何をどう変えたか」が表示される
3. **進行状況の可視化**: POST /mocks/{id}/revise/stream (SSE) —
   stage (HTML 読み込み中 → ワンダが HTML を生成中 → 保存中) + 生成済み文字数
   (実測) を逐次配信。スタジオの作業中バブルが「ワンダが HTML を生成中… 4,200 文字
   · 42 秒」のように実値で更新される (llm_chain に llm_stream を追加 — relay の
   delta をそのまま実況)
4. **会話の文脈**: 同一画面チェーンの過去の修正指示 (最大 5 件・古い順) を
   user prompt に「これまでの指示履歴 (文脈として維持すること)」として同梱 —
   ワンダは会話の流れを知った上で改訂する

## 実 e2e (再現条件そのもの / e2e-responsive-revise.txt)

実スキル 3 本 (81KB) をワンダに装着し、固定 1200px テーブルレイアウトの
非レスポンシブなモック (会員登録フォーム) に対して実機と同じ指示
「スマホサイズでのレスポンシブができていないですこれを修正してください」を
実 Bridge + 実 claude (relay) で実行:

- SSE: loading → generating (progress 1512 chars) → saving → result (26 秒 —
  修正前の実機は 97 秒超)
- **構造保持**: タイトル・入力欄・手順・ボタン文言すべて残存 / **TaskFlow・
  サンプルシェルの混入ゼロ** / viewport meta + @media (768px 縦積み) 追加
- **サマリー実値**: 「viewport メタタグの追加と、テーブルレイアウトを 768px 以下で
  縦積みに切り替えるメディアクエリ・入力欄の幅可変化を行い、スマホ表示時の
  はみ出しを解消しました。あわせてプロジェクト規定のメインカラー・アクセント
  カラー・角丸 12px・見出しフォントを適用しています。」
  (GAP-143 のデザインノート学習内容まで正しく効いている)
- 全 10 チェック PASS (E2E_OK: True)
