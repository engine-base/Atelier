# GAP-167: ナレッジ候補の採用 / 却下 — 全部は溜めない

経営者指摘 (2026-08-19):
「この形式とか、しかも全て溜めるのはノイズになるし、ちゃんとどれを入れるかなども
 できる状態になっているのか？？」

**ご指摘のとおりでした。** GAP-164 は拾ったノウハウを**そのままナレッジに入れて**
いました (削除はできるが、後から掃除する形)。**入れる前に選ぶ**形に変えました。

## 元々 → 今

| | 元々 (GAP-164) | 今 (GAP-167) |
|---|---|---|
| 保存先 | 直接 `knowledge_nodes` | **候補** (`knowledge_candidates`)。人が採用して初めてナレッジ |
| 選別 | 無し (溜まってから消す) | **採用 / 編集して採用 / 却下** をその場で選ぶ |
| 却下したもの | 概念なし (また出る) | **同じ題は二度と提案しない** (workspace × title の一意制約) |
| 候補ゼロのとき | — | **UI に何も出さない** (それ自体をノイズにしない) |
| 重複 | ナレッジの題だけ照合 | ナレッジ + 候補 (却下済み含む) の題を照合 |

## 選ぶ基準を機械側でも絞っている

- 抽出プロンプト: **一般化できるものだけ**。社名・人名・金額・URL・日付など
  案件固有の事実は書かせない。雑談・進捗報告は対象外。**該当なしなら空**。
- 1 回あたり **最大 2 件**。短すぎる本文 (20 字未満) は捨てる。壊れた応答も捨てる。

## 証拠

API テスト (`TestGap167KnowledgeCandidates` 2 + `TestGap164` 更新 3):
- 候補は一覧に出て、**採用して初めて** `knowledge_nodes` に入る (編集して採用も可)。
  二重採用は 409。
- **却下したものはナレッジにならず、同じ題は自動抽出からも再提案されない**
  (却下後に同じ題で抽出を走らせて `[]` になることを実測)。
- 自動抽出は候補にだけ入り、ナレッジ本体は 0 件のまま (実測)。

Web テスト (`knowledge-candidates` 5):
候補一覧と「採用したものだけがナレッジになる」表示 / そのまま採用 / 編集して採用
(編集内容が API に載る) / 却下と「今後提案されません」/ **候補ゼロなら何も描画しない**。

## 併せて直した回帰

ナレッジ画面に候補セクションを足したことで、既存の S-K01 テストが
「1 番目の GET が /knowledge である」前提と「本文」ラベルの曖昧一致で落ちた。
呼び出し順ではなくパスで特定するよう直し、候補パネル側も**候補の形をしていない
応答は描画しない**よう防御した。
