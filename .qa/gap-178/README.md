# GAP-178: 「env を消さないと使われる」設計をやめる

経営者指摘:
1. 「削除したわけではないよね？？ 一旦 API は使わない流れ（サブスクで実現できたから）に
   しただけですよ。もしかするとこの場合も出てくるので。わかってますよね？？」
2. 「あと env 消さないと使われる設計もおかしいですよね？？」

**両方そのとおりです。**

## ① 削除していないことの確認

API 経路は**一切消していません**。「既定で黙って課金されない」ようにしただけで、
配線は全部そのまま残っています:

| 残っているもの | 場所 |
|---|---|
| Anthropic API 呼び出し | `llm_chain.py` (`AsyncAnthropic`) |
| `AnthropicClient` 本体 | `src/llm/anthropic.py` |
| BYOK (顧客自身の API キー) | `services/byok_keys/` + `routes/byok_keys/` |
| 運営バッチ (ナレッジ自動キュレーション) | 元から運営負担のまま (変更なし) |

**使いたくなったら env 2 つで即復帰**します (証拠 `routes.txt` の ④):
```
ATELIER_LLM_PROVIDER=api
ATELIER_ALLOW_API_BILLING=1
→ AI 実行経路: api / 費用: 運営の Anthropic API 従量課金
```
「本人サブスクを主、Bridge 未接続のときだけ運営が肩代わり」もできます (⑤)。

## ② 「env を消さないと使われる」設計の是正

GAP-175 の時点では、**環境変数の「不在」に正しい挙動が依存**していました
(`ATELIER_LLM_PROVIDER` が未設定なら本人サブスク)。この形は:

- 昔設定した値が残っているだけで、黙って別の経路 = **別の支払者**になる
- 打ち間違い (`=rely` 等) が黙って経路を変える
- 「今どの経路で動いているか」がサーバーの env を読まないと分からない

を全部踏みます。実際に私も「Mac の .env から消してください」という運用回避を
お願いしてしまいました。それが設計の敗北です。

**直した内容**:

1. **決定箇所を 1 つに** — `services/chat_sse/llm_route.py::resolve_llm_route()`。
   env を読むのはここだけ。`relay_mode_enabled()` / `api_billing_allowed()` /
   `subscription_mode_enabled()` は全部これに委譲。
2. **怪しい設定は安全側 (本人サブスク) へ倒して必ず警告**
   - 未知の値 (`=rely`) → 本人サブスク + 「綴りを確認してください」(③)
   - `=api` だが課金許可なし → **運営に課金せず**本人サブスクへ + 理由を明示 (②)
   - キーはあるが使わない → 「使いません (運営に LLM 費用は発生しません)」と明言
   - 肩代わり有効 → 「運営に LLM 費用が発生します」と**必ず**警告
3. **消し忘れが事故にならない** — 昔の値が残っていても支払者は変わらず、
   なぜそうなったかが文章で出る。もう env を消して回る必要はありません。
4. **見える化** — 起動ログに 1 行 (⑥) + **運営ダッシュボードの「プラットフォーム
   健全性」に「AI 実行経路 / 費用の出どころ」を常設** (⑦ / スクショ)。
   サーバーの env を読まなくても、画面で今の状態が分かります。

## 証拠

- `routes.txt` — 5 パターン + 実サーバーの起動ログ + 実 `/admin/health` 応答
