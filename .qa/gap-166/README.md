# GAP-166: Excel / PDF を「本人の Claude Code」に直してもらう

経営者指摘 (2026-08-19):
「でもこれ Claude Code ではできるくない？？ サブスクのプランでやっているし
 できるはずだけどどうしてできないの？？ できる状態にして欲しい」

**おっしゃるとおりです。** GAP-163 でサーバー側にできることの線を引きましたが、
**本人の PC で走る Claude Code はファイルそのものを開いて直せます**
(openpyxl / pypdf 等を自分で使える)。その経路を通しました。

## 元々 → 今

| | 元々 | 今 |
|---|---|---|
| Excel の値の編集 | 画面の表で可 (GAP-163) | 同じ |
| 書式つき Excel・数式・レイアウト | **サーバーでは無理** → 諦めていた | **Claude Code に依頼** → 直った版が新バージョンで戻る |
| PDF の編集 | **できない、と断るだけ** | **Claude Code に依頼** → 直った版が新バージョンで戻る |
| 費用 | — | **本人の Claude サブスク** (運営費用ではない) |
| Bridge オフライン時 | — | **enqueue せず 503 で正直に断る** (黙って待たせない) |

## 仕組み (既存の Bridge 経路をそのまま使う)

1. `POST /outputs/{id}/ai-file-edit` … 認可は RLS で確認 → ジョブを積む
2. **作業場 seed を拡張** — プロジェクトのファイル成果物 (xlsx/pdf 等) の最新版を
   base64 で配る (GAP-141 の seed + GAP-161 の添付配布と同じ仕組み)
3. Claude Code が「作業場の〈ファイル名〉を〜のとおり直して**同じ名前で上書き保存**」
   を実行 (形式は変えない・指示に無い箇所は触らない、と system prompt で拘束)
4. Bridge が変更を検出 → 既存の取り込み経路で **新バージョン**として登録

UI は成果物ビューアの中に「AI にファイルごと直してもらう（あなたの PC の
Claude Code で実行）」。Excel の表編集と併設し、PDF など表にできない形式でも出ます。

## 証拠

API テスト `TestGap166AiFileEdit` (3):
1. **Bridge オフライン → 503 で断り、ジョブは 1 件も積まれない**
2. **PDF でもジョブが積まれる** — prompt にファイル名・指示・「同じファイル名で
   上書き保存」が入り、system prompt に「形式は変えない」、tools_mode=auto、
   requested_by=本人、status=queued
3. **作業場 seed に対象ファイルの実体 (base64) が含まれる** = Claude Code が開ける

Web テスト `sheet-editor` (GAP-166 分 2): PDF (409) でも AI 依頼 UI が出て実 payload を
送ること / Bridge オフラインを正直に表示すること。

**この環境での限界 (正直に)**: Bridge を実際に接続した end-to-end (ファイルが直って
戻ってくるところ) は、この環境に Bridge が無いため未実測です。ジョブが正しく積まれる
ところまでと、作業場にファイルが配られるところまでを実データで確認しています。
