# GAP-171: 成果物改訂・営業ドラフト・フェーズ提案・修正提案を「本人の Claude サブスク」へ統一

確定アーキテクチャは **「全ユーザーが自分の PC の Bridge = 自分の Claude サブスクで
実行する」** (GAP-134 / GAP-138)。しかし実際には、**画面から使う AI 機能の半分が
運営の `ANTHROPIC_API_KEY` を直接叩いていた** — つまり運営の従量課金で動いていた。

## 元々どうだったか → どうしたか

| 機能 | 担当 | 修正前 | 修正後 |
|---|---|---|---|
| 成果物の改訂 | スティーブ | **運営の API キー直叩き** (未設定なら 503) | relay → agent_sdk → API キー → fake の費用順チェーン |
| コメントからの修正提案 / 適用 | スティーブ | 同上 | 同上 |
| 営業ドラフトの生成 | トニー | 同上 | 同上 |
| 次フェーズの提案 | ジャービス | 同上 | 同上 |
| モックの生成・改訂 | ワンダ | (GAP-138 で対応済) | — |
| 出力デザインテンプレ | ワンダ | (GAP-158 で対応済) | — |
| ナレッジ自動キュレーション | 運営バッチ | 運営の API キー | **意図どおり運営負担のまま** (対象外) |

- 共通化: `services/chat_sse/llm_chain.py` に `llm_complete_or_injected()` を追加。
  テスト注入の `client` はそのまま差し替え口として残し、本番経路だけをチェーンに乗せた。
- `meta.model` は **「どの実行経路 = 誰の費用で作られたか」** を記録するようになった
  (`relay` / `agent_sdk` / `api` / `fake`)。GAP-138 のモックと同じ表記に揃えた。
- 未接続 (503) は 4 画面すべてで **その場に接続フロー** が出る (GAP-168 と同じ扱い) —
  成果物ビューア / 営業ドラフト / 工程 (フェーズ提案)。文言も
  「◯◯ AI が未設定」から「お使いのパソコン (Bridge) が未接続」に是正した
  (未設定なのは運営ではなく利用者の PC なので)。

## 証拠 (実 API + 実 Bridge。**運営の API キーは設定していない**)

API は `ATELIER_LLM_PROVIDER=relay` かつ `ANTHROPIC_API_KEY` 未設定で起動している。
つまり運営の従量課金は物理的に使えない状態。そこへ headless Bridge を実接続した。

```
PASS  改訂が受理される (運営キー無しでも成立)
PASS  新しい版が作られた
PASS  実行経路が relay (= 本人の Claude サブスク) と記録される
PASS  作成者はスティーブ
PASS  本人の PC が返した内容が実体に入っている
body: <html><body><h1>GAP-171</h1><section id="added-by-bridge">本人の PC の Claude が追記したセクション</section></body></html>

PASS  営業ドラフトが生成される (運営キー無し)
PASS  トニーの実行経路が relay (本人サブスク)
PASS  生成者はトニー

--- DB 実測 (phase_proposals.model) ---
次フェーズ: 結合テスト | model=relay
```

`roundtrip.txt` が実行ログ。**正直な但し書き**: `claude` 本体はこのコンテナに無いので
スタブに置き換えている (GAP-169 と同じ方針)。証明しているのは
「運営の課金経路を断っても、本人の PC 経由で実際に生成・改訂が成立し、
その結果がツールに戻ってくる」配線であり、生成物の品質は実機での話。
