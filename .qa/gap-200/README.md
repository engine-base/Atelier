# GAP-200 — 意味検索・文字起こしをサーバーで動かす

## 何が問題だったか

本番 Docker イメージに `--extra localrag` を入れていないため、
**fastembed / faster-whisper がそもそも入っていない**。それなのにコードは
「ローカル埋め込み」「このサーバー内の faster-whisper」と表示しうる状態で、
実際には意味検索は文字一致に落ち、文字起こしは利用者の PC 頼みだった。

## 結論: 「入れられるようにする」が正解、「既定で入れる」は正解ではない

実測した費用がはっきりしている。

| | 既定 (入れない) | サーバー実行 (入れる) |
|---|---|---|
| イメージ増加 | 0 | **+約 2.6GB**（実測: 埋め込み 2.1GB / whisper-small 464MB） |
| 必要メモリ | 256MB のまま | **1GB 以上・推奨 2GB**（実測: 埋め込み 652MB〜1,554MB / whisper 302MB〜1,007MB） |
| Fly.io 月額 | $2.02 | **$11.11**（2GB・24 時間換算） |
| 誰の費用か | — | **運営** |
| 利用者の PC で動かした場合 | **0 円** | — |

**運営費用が約 5 倍**になる。だから既定は入れない。ただし
「入れたい」と判断したときに**安全に入れられる**ようにした。

## 入れられるようにしたもの

1. **`Dockerfile` の `ARG INSTALL_LOCALRAG`（既定 0）** — 1 のときだけ
   localrag extra を入れる。
2. **モデルはビルド時に取り込む**（`apps/api/scripts/prefetch_models.py`）。
   実行時に落としに行くと「最初の 1 人だけ数分待たされる」「ディスクや権限で
   失敗しても『検索の精度が落ちた』としか見えない」「machine が入れ替わるたびに
   落とし直す」になる。**1 つでも取得に失敗したらビルドを失敗させる** —
   「入れたつもりで入っていない」イメージを本番へ出さないため。
3. **`deploy.yml` の `server_ai` 入力（既定 false）** — true のとき
   `--build-arg INSTALL_LOCALRAG=1` を渡す。
4. **VM チェック** — `server_ai=true` なのに `fly.toml` の memory が 1024MB
   未満なら **deploy 前に exit 1**。メモリ不足のまま入れると OOM で落ちるだけで
   原因が分からない。
5. **実態の可視化** — `src/services/server_ai.py` が **宣言ではなく実際の import**
   で判定し、起動ログと運営画面（S-T01「サーバー側 AI」行）に出す。
   **「入れたつもりで入っていない」は warn として検出**する。

## 実 e2e (`e2e-output.log`)

```
[1] 既定は「入れない」    → ARG INSTALL_LOCALRAG=0 / extra は 1 のときだけ
[2] 有効化して実際に DL  → 2.6G (whisper-small 464M ほか) を実測、確認後に削除
[3] VM 不足では止まる    → 今の 256MB では server_ai=true の deploy が止まる
                          2048mb / 1gb 表記の換算も検証
```

`prefetch_models.py` は**本物のモデルを実際にダウンロードして**成功した
（埋め込み・文字起こしとも OK）。容量もその場で測っている。

## 使い方（入れると決めたとき）

1. `fly.toml` の `[[vm]] memory` を `"2048mb"` に上げる（月額 $2.02 → $11.11）
2. GitHub Actions の deploy を **`server_ai` にチェックを入れて**手動実行
3. 運営画面 S-T01 の「サーバー側 AI」行が
   「このサーバーで 意味検索 / 文字起こし を実行します (運営の費用)」になる

戻すときは `server_ai` を外して deploy し直し、memory を戻す。
