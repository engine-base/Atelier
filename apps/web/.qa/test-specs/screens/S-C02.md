> pytest: `tests/routes/test_employee_icon.py` 8 件。vitest: `tests/bundle-i/uc07-employee-editor.test.tsx`（+3 件）。

- **POST /ai-employees/{id}/icon-upload-url**: 署名付きアップロード URL 発行（2 段階アップロードの 1 段目、
  meetings と同じ Supabase Storage 契約）。MIME は png/jpeg/webp のみ（それ以外 415）、512KB 超は 413、
  storage 未設定は 503（握り潰さない）。bucket/path 規約 `avatars/ai-employees/{id}/{uuid}/{sanitized}`。
- **PATCH icon=storage_path** で確定（既存 PATCH — audit 記録も既存フロー）。icon 列は
  lucide 名 or storage path の両対応（path 判定は "/" 含み）。
- **GET /ai-employees/{id}/icon-url**: icon が path のときの署名付き閲覧 URL（TTL 1h）。
  lucide 名/未設定は 409。
- **S-C02 UI**: モックの「画像アップロード」(outlined) を復元。file input → client 側事前検証
  （型/512KB — API を呼ばず即時 inline error）→ 署名付き URL へ実 PUT → PATCH → 再取得で
  ヘッダ/プレビューの `<img>` 実描画。「頭文字に戻す」で解除可。storage 未設定 (503) は
  「ストレージが未設定のため…」の誠実表示。
