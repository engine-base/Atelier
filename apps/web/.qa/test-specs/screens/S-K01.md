## GAP-012 是正 (2026-08-04) — バックリンク (参照元逆引き) の実装

モックの「バックリンク（4）」節 (タスク/ADR/リスク文書/機能仕様の参照元一覧) は
参照元逆引き API 不在で撤去していた。参照の実データ源を新設して是正:

- **knowledge_references テーブル** (migration `t-d-99zc`): (knowledge_id,
  referrer_type, referrer_id) unique + context + reference_count +
  last_referenced_at。RLS は knowledge_nodes の可視性をサブクエリで継承
  (バックリンクの可視性 = 対象ナレッジの可視性。R-T08 越境は 404)。
- **書込 (実参照経路)**: チャット SSE (`services/chat_sse.stream_chat`) が
  RAG で実消費したナレッジを assistant 応答永続化と同一トランザクションで
  upsert (`referrer_type='chat_thread'`, context「チャット応答で参照（RAG）」)。
  同一スレッドの再参照は reference_count++ に畳む。referrer_type は
  task / decision / feature も同型で受ける (書込元実装時に行が生まれる —
  偽装挿入はしない)。
- **逆引き API**: GET /knowledge/{id}/references — referrer_title を
  chat_threads/tasks/decisions から実解決。RLS 不可視・削除済の参照元は除外。
  S-E01 の作成ダイアログに題名欄が無く title=null が正規状態のため、可視の
  無題スレッドは「無題スレッド」に fallback (監査ラウンド 1 で検出した実挙動)。
- **UI**: NodeDetail バックリンク節 — 件数見出し「バックリンク（N）」、行 =
  参照元名 + 種別ラベル (チャット/タスク/ADR/機能仕様) + 文脈 + 「n 回」
  (再参照 1 回は非表示)。0 件は「まだ参照されていません」の誠実表示。

検証: pytest 4 (実 SSE ストリーム経由の記録 / dedupe count=2 / R-T08 越境 404) +
vitest 2 (バックリンク描画 / 空状態) + 実操作監査 `.audit-k01-backlinks.mjs`
3 連続 ALL PASS (実チャット送信 → knowledge_references DB 突合 → 再送信で
count=2 → S-K01 実描画確認、シード削除で再実行可能)。
