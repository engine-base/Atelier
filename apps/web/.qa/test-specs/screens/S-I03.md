## GAP-026 是正 (2026-08-04) — 運用操作系 (Bridge 接続/並列枠/一時停止/昇格/取消/停止/表示切替/経過)

> 監査スクリプト: `apps/web/.audit-i03-dispatch-ops.mjs`（3 連続 ALL PASS・再実行可能）。
> pytest: `tests/routes/test_executions.py::TestDispatchOps` 6 件 + dispatcher 回帰 12 件。
> vitest: `tests/bundle-i/uc16-execution-monitor.test.tsx` +5 件 (12 passed)。bridge: 24 passed。
> migration `t-d-99zh`: dispatch_control (singleton) + bridge_workers + tasks.dispatch_promoted_at。

- **① Bridge 接続バッジ**: Bridge アプリが毎 poll `POST /bridge/ping` (BridgeAuth) で presence を
  upsert (apps/bridge dispatcher に実装)。S-I03 は /bridge/status の workers (90 秒以内 = 接続中) から
  「ローカル Claude Code に接続中 · Bridge vX · host」/「Bridge 未接続」を誠実表示。
- **② 同時実行枠 + すべて一時停止 + 順番待ちから 1 件追加**: 実 parallel_limit/available_slots 表示。
  `POST /dispatch/pause|resume` — paused 中は実 /kanban/pick が no_available_task (実行中は継続)。
  `POST /dispatch/promote` — 最古 queued を dispatch_promoted_at で昇格 (pick は promoted 最優先。
  Bridge がローカル起動する構造のため API は spawn しない — 「次の空き枠で最優先開始」の誠実文言)。
- **③ キュー取消**: `POST /tasks/{id}/dispatch-cancel` (queued 限定 409 guard、ready へ戻す)。
- **④ セッション停止**: `POST /tasks/{id}/dispatch-stop` (2 段階確認 UI) — dispatch=reclaimed +
  blocked + 実行 execution を cancelled で閉じる (以後の complete は取り込まれない)。
- **⑤ 表示方法 カード/一覧/ログ集約**: 一覧 = 全区分テーブル。ログ集約 = `GET /executions-events`
  (実 task_executions から開始/終了イベントを導出、10 秒 poll)。推測ログは生成しない。
- **⑥ 経過時間/残り**: 経過 = 実 started_at からの実測 tick (1 秒)。残りは「見積比 残り N 分」
  (estimated_hours 由来と明示、超過は「見積超過 +N 分」— 推測を装わない)。
- audit: dispatch.paused/resumed/promoted/cancelled/stopped。R-T08: 他 WS タスクへの操作は 404。
