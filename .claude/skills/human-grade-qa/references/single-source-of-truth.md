# 単一正本（Single Source of Truth）と仕様ドリフト防止

鉄則3 の具体手順。 «仕様書が途中で変わった/増えた» を構造的に消すための、 どのプロジェクトでも使える運用。

## 1. 正本は1つに収束させる

- テスト仕様の正本は **マトリクス1冊**（`<案件>_テスト検証_完了版_<版>.xlsx` 等）。
- 「主要機能ぶん」と「新機能ぶん」を **別ファイルの正本として並立させない**。 参照先・提出物・ファイル名は常に1つ。
- 部分仕様（特定機能だけの md/csv）は **ソース**であって正本ではない。 ユーザに渡すのは常に統合済みの完全版1冊。

## 2. 再現可能なパイプライン（完成物は手で触らない）

正本は必ず **ソース → ビルド → 生成物** の一方向で作る。 完成 xlsx を直接編集しない。

```
spec ソース            実行結果                生成（決定論的）
─────────────         ────────────           ──────────────────────
screens/*.md      ┐
journeys/*.md     ├─→  results/*.(md|csv) ─→  build_matrix.py ─→ 完了版.xlsx / CSV
axes/*.md         ┘                            （ID で突合・status 再適用）
```

- **status はソース（results）が真実。** spec md の「結果」列は常に「未着手」にしておき、 ビルド時に results から再適用する。
- これにより (a) いつでも同じ生成物に再現でき、 (b) 生成物が壊れても **ソースから100%復元**でき、 (c) 「手で1件だけ緑にした」捏造が起きない。

## 3. アプリが途中で変わったら「完全な超集合」に作り直す

QA 期間中の修正/機能追加は、 次を **必ず**行う:

1. 変更点を **全観点で TC 化**: 表示 / 操作（全ボタン・全フォーム）/ バリデーション / エラー / 境界（0・空・重複・最大）/ セキュリティ / レスポンシブ。
2. 既存ソースと **同じ形式**で `screens/<feature>.md` 等に追加（別フォーマットの離れ小島にしない）。
3. パイプラインを **再実行して完全版を1冊**再生成（古い正本に継ぎ足さない）。
4. 版を上げ、 changelog に1行（§5）。

> 「あとから足す」のではなく「毎回つくり直す」。 これが並立・部分化を防ぐ唯一の方法。

## 4. 再生成の前にソースをバックアップ／コミット

- `screens/` `journeys/` `axes/` と `results/` を **再生成前にコピー or git commit**。
- 生成スクリプトの事故・ファイル消失があっても、 ソースから正本を復元できる状態を常に保つ。
- 推奨: `.qa/` をリポジトリにコミット（少なくとも spec ソースと結果 CSV）。 untracked のままだと事故時に git 復元できない。

## 5. 変更履歴（changelog）テンプレ

正本と同じ場所に `CHANGELOG.md` を置き、 TC 総数が動くたびに1行追記。 report 時にも «前回比 +N件・理由» を必ず添える。

```
# テスト仕様 変更履歴
| 版 | 日付 | TC総数 | 差分 | 内容・理由 |
|----|------|-------|------|-----------|
| v3 | 2026-06-26 | 1977 | +46 | パスワードのハッシュ化/初回表示/再発行/移行 機能追加に伴い password-security を全観点でTC化 |
| v2 | 2026-06-25 | 1931 | +0  | バグ26件修正を反映（TC追加なし・status更新のみ） |
| v1 | 2026-06-22 | 1931 | new | 初版（全画面×全要素・全ルート・RLS・0状態・ジャーニー） |
```

## 6. 提出前セルフチェック

- [ ] 正本は1冊か（新機能を別仕様として並立させていない）
- [ ] マトリクスはソースから再生成したものか（完成物に手で足していない）
- [ ] 前回から TC が増減したなら、版と changelog に理由を書いたか
- [ ] spec ソースと結果 CSV をバックアップ/コミットしたか
- [ ] report に «前回比・理由» を1行添えたか

1つでも No なら、 その仕様書は **未完**。
