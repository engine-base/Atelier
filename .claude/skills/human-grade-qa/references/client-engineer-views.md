# 2系統の成果物 — クライアント版／エンジニア版（鉄則4の詳細）

テスト仕様の最終成果物を、 非エンジニア（クライアント）向けと開発・QA 向けに分けて出すための、 どのプロジェクトでも使える規約。

## なぜ分けるか

エンジニアの語彙のままだと非エンジニアは読めない（«どの画面か» «死にボタンとは» «network/Playwright/RLS» が不明）。
クライアントが確認するのは **実際の画面操作での挙動** だけ。 裏取り（証拠）は別系統に隔離する。

## ① クライアント版（非エンジニア向け）

- **対象**: 人が画面で **操作・目視できる挙動だけ**。 画面で見えない技術専用 TC は載せない（→②へ）。
- **言語**: 平易な日本語。 専門用語を1語も出さない。
- **タブ**: 1画面＝1タブ、 **日本語の画面名**（内部キー `home`/`admin-students` ではなく「ホーム画面」「受講者管理」）。
- **列**（クライアントが見慣れた表計算の形）:

  | ID | 画面 | テスト観点 | テスト項目 | 前提条件 | 操作手順 | 期待結果 | 結果 | 備考 |

- **結果列**: 「完了」等（PASS/検証OK のような社内表記にしない）。
- **操作手順／期待結果**: 「○○画面を開く」「○○を入力して××を押す」「△△が表示される／次の画面に進む」のように、
  人の動作と目に見える結果で書く。 URL・APIパス・HTTPコード・コード参照は書かない。

## ② エンジニア版（裏取り）

- **対象**: 全 TC。 画面で見えない技術専用軸（全ルート sweep・RLS・0状態・鍵/環境変数・移行スクリプト・
  コード/DB 突合・契約テスト）も**すべて**含む。
- **列**: ①の列 ＋ **確認方法/HTTP** ＋ **根拠・証拠（network / console / Playwright spec 名 / DB クエリ / HTTP コード）**。
- 技術用語OK。 ①と同じ ID を保持して相互参照できるようにする。

## 用語の言い換え表（クライアント版・抜粋）

| 裏側の表現（②） | → クライアント版（①） |
|---|---|
| 死にボタン／ハンドラ+API実在 | ボタンを押すと正しく動作するか（反応しないボタンが無いか） |
| 死にリンク／UI断線・到達性 | 画面の導線（リンク）が切れていないか |
| 貫通（create→別GET→DB突合） | 画面で最後まで確認（登録した内容が画面に出る） |
| POST /api/... が200・Cookie発行・router.push | （ログイン等が）でき、次の画面に進む |
| role=alert にエラー文 / 401・422 | 「○○」とエラーが表示され、進めない |
| required でブロック・API未発火 | 空のままでは送信できない |
| enum 不一致 / 区分値 | 区分（種別）の指定 |
| RLS / 行レベル権限 | 他人のデータが見えないこと（権限） |
| レスポンシブ / 320・768・1440 | スマホ・タブレットでも崩れない |
| 冪等 / idempotent | 繰り返し実行しても安全 |
| network / console / Playwright / DB 突合 | （クライアント版には出さない＝②へ） |

> プロジェクト固有の用語が出たら、 この表に1行追記してから言い換える。 «裏側の語をそのまま残す» のは①の不合格。

## 画面で見えない＝①から外す（②のみ）判定の目安

- 手順が `curl` / DevTools / コードを読む / `select`（DB直接）で始まる
- 観点が「ルート実在」「DB突合」「環境変数/鍵」「契約/単体」「RLS隔離」等、 画面操作を伴わない
- 証拠が network/console/Playwright だけで、 ユーザーの目に見える変化を伴わない

## 完全性の証明（漏れ0）

クライアント版から «画面で見えるもの» を間引いていないことを、 **画面ごとに件数照合**して示す:

```
全TC（②） = ①クライアント可視 + （②のみ：技術専用）
例) ログイン 32 = 20（画面可視）+ 12（技術専用: ルート確認/DB突合/コード確認 等）
```

各画面でこの式が成り立つことを確認する。 成り立たない（合計が合わない）＝どこかで取りこぼし＝不合格。

## 生成は正本から決定論的に（鉄則3と一体）

- 2系統とも **同じ正本（マトリクス／spec ソース）から自動導出**する。 手で選り分けない（漏れる）。
- 除外は «画面で見えない技術専用» の **定義済みパターン**のみ。 それ以外は全件①に通す。
- 納品形式は xlsx 2ファイル（①クライアント版／②エンジニア版）を既定とし、 そのまま表計算へ取り込める形にする。
