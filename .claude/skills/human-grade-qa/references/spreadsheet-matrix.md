# spreadsheet-matrix — 画面別タブの検証マトリクス出力（スプレッドシート対応）

検証結果を「**画面ごと・細粒度・タブ分け**」のマトリクスとして出力し、最終的に**全行が検証済み(pass/fail+証拠)**
になった状態を一望できるようにする。state.json(正本)から派生生成し、任意のスプレッドシートにインポート、
または接続済みの表計算 MCP/コネクタへ直接書き込む。

## 正本と派生
- **正本は state.json**（各 TC の status / evidence / cluster 等）。md/html/csv/シートは派生。
- 派生生成: `scripts/render_matrix.sh <run-dir> <out-dir>` → `<out-dir>/matrix/<tab>.csv` を出力。
- 実行中も TC 完了ごとに state.json を更新 → 再生成すればシートが最新化。

## タブ構成（★タブはプロジェクトごとに動的に決まる）

**画面タブは固定リストではない。** タブ名＝**そのプロジェクトの実画面**であり、プロジェクトごとに変わる。
必ず対象プロジェクトから動的に列挙する（`screens.json` / モック一覧 / ページルート(`app/**/page.*`,
`pages/**`, ルータ定義) を走査して画面集合を得る）。`ログイン`/`ユーザー一覧`等は**ある一例の画面名**であって、
別プロジェクトでは `会話`/`タスク`/`ダッシュボード`等になる。**画面名をハードコードしない。**

- **画面タブ**: 検出した画面 1 つにつき 1 タブ(=1ワークシート=1CSV)。 行数はその画面の表面積ぶん（導出・上限/目標なし＝鉄則2-8）。
- **軸タブ**: 画面に依存しない横断軸を固定で持つ → `summary` / `routes` / `rls-matrix` / `zero-state` /
  `agent-behavior` / `journeys`（プロジェクトに該当軸が無ければそのタブは空 or 省略）。

### 画面タブの列（推奨デフォルト。プロジェクトに応じて増減してよい）
実運用シートの 9 列を基に、**証拠列を明示**したもの（このスキルは「証拠なき PASS は捏造」が鉄則のため、
証拠列を独立させて埋め忘れを防ぐ）。下記を既定とし、プロジェクトの事情で列を足し引きして良い:

| 列 | 内容 |
|---|---|
| ID | 画面内連番 (1,2,3…) |
| テスト観点 | 大分類（画面表示/入力/バリデーション/一覧/詳細/権限/エラー/レスポンシブ/状態継続…） |
| テスト項目 | 具体的に何を確認するか（フィールド名・列名・ボタン名を明記） |
| 前提条件 | セッション・データ・権限・画面状態（無ければ `-`） |
| 操作手順 | 1. … 2. … と誰でも再現できる粒度 |
| 期待結果 | UI/API/DB/ログで何が起きるか（検証手段も明記） |
| 結果 | **完了 / 未着手 / FAIL**（実行後に更新。固定語彙） |
| 証拠 | screenshot/SQL/network の相対パス（完了なのに空は不可＝鉄則1） |
| 備考 | 補足・未実装理由・cluster |

> 列はプロジェクト次第で調整可（例: CSV出力がある画面は「列構成」「文字コード」行を増やす、
> モバイル対応なら「ブレークポイント」列を足す等）。**ベストと思う列にしてよい**が、最低限
> 「観点・項目・手順・期待・結果・証拠」は外さない（結果の判断根拠が辿れなくなるため）。
> status(state.json) → 結果: `passed→完了` / `failed→FAIL` / `planned→未着手` / `blocked→FAIL`(備考に理由)。

### 軸タブの列（推奨デフォルト）
| タブ | 単位 | 主な列 |
|---|---|---|
| `summary` | 集計 | tab(画面/軸名), total, 完了, FAIL, 未着手, 検証率% |
| `routes` | 1ルート(メソッド)=1行 | method, path, db_op, schema_ok(R2), http(R3), systemic_class(a〜g), 結果, 備考 |
| `rls-matrix` | テーブル×ロール×操作=1行 | table, role, op, 期待(allow/deny), 実測, cross_tenant, 結果 |
| `zero-state` | 0状態/初期構築の1チェック=1行 | step, 期待, 実測, 結果, 備考 |
| `agent-behavior` | AI対話シナリオ=1行 | scenario_id, 意図, expected_tool, expected_side_effect, tool_calls, db_diff, 結果 |
| `journeys` | フロー1ステップ=1行 | journey, step, 操作, 期待, 結果, 備考 |

> ゴール: 検出した**全画面タブ**の「結果」が **完了**、かつ routes/rls/zero-state/agent も完了。
> 「画面ごとに徹底」= 画面タブを開けば 1 画面の全チェック（表面積ぶんの全行・件数は導出）が一覧化される。

## CSV フォーマット規約
- UTF-8 (BOM付きにすると一部スプレッドシートで文字化け回避)。1 行目はヘッダ。
- カンマ・改行・引用符を含むセルは `"` で囲み、内部の `"` は `""` にエスケープ。
- status は `passed|failed|planned|blocked` の固定語彙(summary 集計と一致させる)。
- evidence 列は証拠への相対パス(screenshots/… / artifacts/… / SQL / network)。空 passed は不可(鉄則1)。

## 表計算 MCP/コネクタへの直接更新（接続時）
接続済みの表計算サービス(例: スプレッドシート系 MCP / コネクタ)があれば、CSV ではなく**直接更新**する:
1. ツール検索でシート系ツール(create/append/update worksheet 等)を探す。無ければ CSV にフォールバック。
2. **タブ=ワークシート**として作成/更新(summary/screens/routes/…)。
3. ヘッダ行＋各 TC 行を upsert。status 列は条件付き書式に向くよう固定語彙で出す。
4. 既存シートを更新する場合は、test_id をキーに**冪等 upsert**(重複行を作らない)。
5. 機微情報(PII/トークン)はシートに書かない(鉄則の秘匿に準拠)。

> 接続が無い/不明な場合は CSV を出して「このCSVをスプレッドシートにインポートしてください(または対象シートのURL/接続を教えてください)」と案内する。勝手に外部送信しない。

## 運用（最終的に全検証済みにする）
- 計画時(test-plan): 全タブの行を**先に**起こす(status=planned)。これが「やるべき検証の全量」。
- 実行時(full/diff): 1 行ずつ実機で潰し status と evidence を更新 → シート/CSV 再生成。
- 完了判定: summary の検証率が 100% かつ failed/ blocker=0、未証明 passed=0(audit_evidence.sh 通過)。
  routes タブのスイープ完了率(第7軸)も 100% を要求。
