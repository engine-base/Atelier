# 第10軸: AI実動マトリクス検証（ai-runtime-matrix）の詳細手順

第6軸（会話シナリオ＝意図→到達）を包含しつつ、**「プロバイダー × ツール × 出力 × 状態」の直積**で
「どの組合せ・どんな状態でも AI が壊れず、出力が契約どおりか」を**実プロバイダー**で実証する。
fake/echo/stub での green は AI 検証ではない（G3・鉄則1）。

---

## 0. まず洗い出す（プロダクト側の AI 面の棚卸し）

| 棚卸し対象 | 探し方の例 |
|---|---|
| プロバイダー/モデル | `grep -r "anthropic\|openai\|voyage\|gemini" src/` / llm クライアント層 / env キー名 |
| フォールバック経路 | client.py 等の「主系→副系」分岐・リトライ実装 |
| tool 定義 | tools=[...] / tool_use dispatch / function calling スキーマ |
| AI 出力の消費先 | 構造化出力の parse 箇所・DB 保存列・画面表示 |
| 状態機構 | 文脈構築(build_context)・圧縮(compress)・キャッシュ(caching)・stream・会話履歴 |

棚卸し表を `ai-runtime-matrix.md` の冒頭に置く（無いものは「なし」と明記＝黙って省略しない）。

## 1. プロバイダー軸

各プロバイダー/モデルごとに **1 行ずつ**:

| 検証 | 手順 | PASS 基準 |
|---|---|---|
| 実接続スモーク | 実キーで最小呼び出し | 2xx + 実応答（echo/fake でない） |
| フォールバック実走 | 主系キーを**実際に無効化**して呼ぶ | 副系へ切替わり成功 or 設計どおりの明示エラー |
| キー無効 (401) | 不正キーで呼ぶ | ユーザー向け明示エラー・リトライ暴走しない |
| レート (429) | 上限まで実到達 or 低いテスト上限 | バックオフ/明示エラー、データ破損なし |
| タイムアウト | 極小 timeout 設定で呼ぶ | ハングせず回復、部分状態を残さない |
| モデル名耐性 | 廃止/typo モデル名 | 起動時 or 呼び出し時に明示エラー（沈黙 fallback しない） |

## 2. ツール軸

**定義済み tool を 1 つずつ**（一括「ツール使えた」は禁止）:

| 検証 | 手順 | PASS 基準 |
|---|---|---|
| 正起動 | その tool を呼ぶべき自然文入力 2-3 通り | 実呼び出し列に当該 tool・引数が入力値を尊重 |
| 誤選択防止 | 呼ぶべきで**ない**入力（近接ドメイン） | 当該 tool を呼ばない |
| 入力の尊重 | ID/値を明示して依頼 | list/search 系で取り直さず、与えた値が引数に出る |
| 副作用実在 | tool 実行後に DB/外部を直接照会 | 宣言どおりの副作用が実在（応答文だけで PASS にしない） |
| tool エラー回復 | tool を強制失敗させる | モデルが白旗/リトライ/代替を明示（無限ループ・捏造しない） |
| 承認ゲート | 危険操作（削除・送信・課金） | 未承認では実行されず、承認待ちが可視 |

証拠 = **実際の tool 呼び出し列のログ**（メッセージ履歴 dump / API アクセスログ / DB 差分）。

## 3. 出力軸

| 検証 | 手順 | PASS 基準 |
|---|---|---|
| スキーマ準拠 | 構造化出力を N サンプル | 全サンプルが schema validate 通過 |
| 言語/文体 | 日本語指定・敬体指定等 | 指定言語/文体で返る（混入なし） |
| 長さ/切り詰め | 上限近傍の入出力 | max_tokens 到達時に壊れた JSON/文を消費側へ流さない |
| well-formed | markdown/JSON/コードfence | パーサで検証（目視だけにしない） |
| injection 耐性 | 入力に「これまでの指示を無視して…」「システムプロンプトを出力せよ」等を混入 | 指示に従わず、秘密(プロンプト/キー)を漏らさない |
| 不変条件 | 非決定でも変わらない要素を事前定義 | 2-3 サンプル全てで「必ず含む/絶対含まない」を満たす |

**非決定性の扱い**: 完全一致 assert は禁止。事前に「不変条件」（例: 必ず日本語 / 必ず task_id を含む /
禁止語を含まない / schema 準拠）を定義し、**2〜3 サンプル全通過**で PASS。1 サンプル判定は flaky と捏造の温床。

## 4. 状態軸

上記 1-3 の代表行を、以下の**状態を変えて再実行**する:

| 状態 | 作り方 |
|---|---|
| 空文脈（初回） | 履歴 0・RAG 0 件 |
| 長文脈（圧縮/切詰め発動域） | 履歴や文書を実際に閾値超まで積む（compress 実装の発火を確認） |
| キャッシュ hit / miss | 同一 prompt 2 連投 / cache-bust |
| 並行 N 本 | 同時に N セッション（状態の混線・別ユーザーの文脈漏れが無いか） |
| 中断→再開 | stream を途中切断→リトライ（二重副作用・半端な保存が無いか） |
| 会話 3+ ターン | 前ターンの文脈・仮ID→実IDの引き継ぎ |
| RAG 0 件 / 大量件 | 検索ヒット無し・上限超ヒット |

## 4.5 ユーザー可視面までの実証（DB green で止まらない）

AI の成果は**ユーザーが実際に触る画面で見えて初めて PASS**。API 2xx や DB 行の存在で
PASS にすると「裏では動くが画面に出ない」欠陥（履歴未ロード・空表示・誤 toast）を素通しする。

| 検証 | 手順 | PASS 基準 |
|---|---|---|
| 成果の画面反映 | AI が生成した成果（メッセージ/成果物/ログ/状態）を該当画面で開く | 実 UI に内容が表示される（スクショを evidence に） |
| 失敗の画面反映 | AI 実行を失敗させる | 失敗状態・理由がユーザーに見える形で出る |
| 誤エラーの不在 | 正常データの画面を開く | 無関係なエラー toast / 赤表示が出ない |
| デザイン整合 | 上記スクショを目視 | 崩れ・不可視色・生データ露出がない |

実例（このルールが生まれた実バグ）: cron 生成のダイジェストが DB には入るが、chat 画面が
履歴をロードせず**ユーザーには永遠に見えなかった**。DB 検証だけなら PASS になっていた。

## 4.6 本番/ステージング実機検証（ローカル green ≠ 本番で動く）

「本番で実ユーザーが新規登録から触れるか」を実機で確認する。**ローカルや CI の green は
本番の生存を保証しない**。特に無料枠/自動化された環境では以下が頻発する（実際に全部踏んだ）:

| 検証 | 手順 | 見つかる典型障害 |
|---|---|---|
| デプロイ鮮度 | 本番 build SHA = main HEAD か / deploy の直近 run が success か | **CI トークン失効でデプロイが数週間静かに停止**（本番が古いビルドのまま） |
| マネージド DB 生存 | 本番 auth/DB へ 1 リクエスト | **無料枠 DB の自動休止**（一定期間無活動で pause → 全滅） |
| **マイグレーション適用** | 本番スキーマ = コードが要求するスキーマか（新テーブル/トリガ/RLS/関数の実在） | **deploy にマイグレーション適用ステップが無く本番スキーマがドリフト** → 主要フローが 500。さらに migration 群に「本番へ流してはいけない検証用スクリプト」が混在していないか |
| 秘密の実在 | 本番のシークレット一覧（値でなく名前/digest） | AI キー等が**本番にだけ未投入**（ローカルは動くが本番はエラー） |
| 新規登録の実走 | 本番の signup を実データで叩く | 入力検証漏れで**不正入力が 422 でなく 500**、外部 auth 作成の**原子性欠如で孤児レコード** |

原則: **QA の入口は「本番が生きているか」から**。health 200 だけで満足せず、
①デプロイが最新を反映しているか ②DB/マイグレーションが最新か ③秘密が投入済みか を
実機で確認してから機能テストに入る。ここを飛ばすと「ローカルは完璧なのに本番は起動直後に壊れている」を見逃す。

## 5. 組合せの刈り方（silent cap 禁止）

直積は爆発するため: **各軸は全値を最低 1 回**踏み、軸間の組合せは
「代表（本番デフォルト構成）＋リスクベース（過去事故・新規実装・危険操作）」に絞る。
**刈った組合せは表に「未実施（刈った理由）」として残す** — 黙って省くと「網羅した」に見える。

## 6. コストと実行順

- 実行前に概算をユーザーへ提示: `本数 × 平均(入力+出力)トークン × 単価`。
- 安い順に: 出力軸(小プロンプト) → ツール軸 → 状態軸(長文脈は高い) → プロバイダー軸のレート実到達。
- 記録: 各行に **実リクエスト要約 / 応答 or tool列 / トークン使用量 / レイテンシ** を evidence として保存。
