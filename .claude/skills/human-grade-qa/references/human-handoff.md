# Human Handoff — ヒトに依頼する場面とテンプレ

Claude にできないこと（物理 / 法令 / 倫理 / 課金）は明示的にヒトに渡す。
**勝手に推測で進めない**。

## 依頼すべき典型ケース

| カテゴリ | 例 |
|---|---|
| 物理デバイス | 実 iPhone での Face ID / Touch ID、NFC タッチ |
| 外部通信受領 | SMS OTP、電話 OTP、紙の郵送物受領 |
| 生体 / カメラ | カメラ撮影、QR スキャン |
| CAPTCHA / BotID | hCaptcha / reCAPTCHA / Cloudflare Turnstile / BotID |
| 法令判定 | 利用規約変更の妥当性、個人情報保護法判断 |
| 課金 | 本番カードでの決済、銀行送金、暗号資産送付 |
| 実 OAuth | 本番 OAuth provider への接続 |
| 認証情報 | 新規パスワード設定、2FA QR スキャン |
| 物理アクセス | 社内ネットワークからのみ可能な操作 |

## 依頼の出し方

### 計画段階

`test-plan.md` の **「4. ヒトに依頼する項目」** に事前列挙。
こうしておくと、ユーザは実行中に呼ばれても準備済みで対応できる。

### 実行中

該当 TC に当たったら **その場で実行を止めずに先に他を進める**。
ヒト依頼項目は最後にまとめて 1 メッセージで依頼するほうが効率良い。

ただし、ヒトの結果が次のテストの前提になる場合（例: OTP を受け取らないと次に進めない）はその場で依頼。

## 依頼テンプレ

### 単発依頼

```
ヒトに依頼: <要件>

理由: <なぜ Claude にできないか>
やってほしいこと:
  1. <手順 1>
  2. <手順 2>
結果として教えてほしいこと:
  - <観察してほしいもの>
あなたが返してくれた結果を `runs/.../human-results.md` に貼り付けて続行します。
```

### バッチ依頼

```
ヒトに依頼まとめ（計 N 件）

H-01 実 iPhone Touch ID
  手順: 実機で /login → 指紋ログイン
  教えてほしい: 成功 or 失敗、失敗ならエラー文言

H-02 SMS OTP
  手順: 番号 +81-XX で登録 → 届いた SMS のコード
  教えてほしい: 受信したコード / 届かなければ何分待ったか

...

全部終わったら 1 回でまとめて返してくれれば OK です。
```

## 依頼を最小化する工夫

- **stub provider** を実装側で用意してもらう（dev 環境）
- **bypass token** を環境変数で用意（dev のみ）
- **test mode** がある決済 / OTP / 認証は test mode を使う
- **fixtures** をユーザに保存してもらい再利用

実装側に「QA のために stub をいれて」と提案するのも有効。

## 結果の取り込み

ヒトから返ってきた結果は

- `runs/<run>/human-results.md` に貼る
- 該当 TC の `result` に "PASS (human verified)" or "FAIL (human reported: <内容>)"
- 後続テストで使う値（OTP / token）は `fixtures.json` に書いて再利用

## 注意

- ユーザに **本番秘密情報** を貼らせない（テスト用の値で代替）
- 個人情報を `.qa/` ログに残さない（マスク）
- ヒト依頼が連続で 5 件以上ある計画は **計画段階で stub 化を提案**
