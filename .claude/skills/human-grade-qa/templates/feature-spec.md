- **影響範囲（壊れたら何が連鎖して壊れるか）:** 〜
- **失敗時のユーザ実害:**

### 「観点」語彙（必須 6 + 補助）

- **正常** — Happy Path
- **異常** — エラー UI / 5xx / タイムアウト / レート制限
- **バリデーション** — 必須・型・長さ・パターン
- **境界** — 最小・最大・空・Unicode
- **権限** — 未ログイン・別ロール・別テナント・不正トークン
- **復帰** — リロード・別タブ・履歴復元・ブラウザ戻る
- 補助: **リグレ** / **セキュリティ** / **性能** / **整合性**

### 「失敗時の実害」記入のコツ

書きやすい言い回し:

- 「〇〇できなくなる」（機能停止）
- 「〇〇が表示される」（情報露出）
- 「〇〇が DB に残る」（データ破損）
- 「〇〇のコストが発生する」（金銭被害）
- 「〇〇が他テナントから見える」（情報漏洩）

「P0 だから重要」では PM が判断できない。**実害語**で書く。

### 「重要度」語彙

- **P0** — リリースを止める / セキュリティ / データ破壊 / 金銭被害
- **P1** — 通常リリースまでに直す
- **P2** — 直したい程度

### 「結果」語彙（実行後）

- **未実施** / **実行中** / **合格** / **失敗** / **スキップ** / **ブロック** / **不安定**

失敗時は「備考」に **要約 / 期待 / 実際 / 原因仮説 / 回避策 / 再現手順 + root_cause_id** を書く。
root_cause_id は同根の TC で同じ kebab-case 文字列（例 `api-validation-missing`）にする。後で
レポートが自動クラスタ化する。

## 5.5 全インタラクティブ要素 実操作チェック表（★必須・coverage-matrix セクション I）

画面ごとに **全ボタン・全リンク・全フォーム・全タブ・全トグル・全 select を 1 行ずつ**列挙し、 実際に操作した結果を埋める。
**未操作（空欄）が 1 つでも残る画面は `planned`**（«数画面だけ»「同型だから他もOK」を防ぐ）。

| 要素 | 種別 | ハンドラ有 | 叩くAPI(メソッド) | API実在 | 実操作の結果 | 作成→UI反映/DB | 結果 |
|---|---|---|---|---|---|---|---|
| 例: 新規コース | button | ✅ onClick | POST /api/admin/courses | ✅ | モーダル開→作成→一覧に出現 | 別GETで反映＋DB行有 | 合格 |
| 例: 編集 | button | ❌ なし | （PUT /api/admin/courses/[id] 不在） | ❌ | 押しても何も起きない | — | 失敗(死にボタン) |

- **ハンドラ有/API実在 が両方 ✅ かつ 実操作で動く** まで「実装済み」と判定しない（鉄則2）。
- 作成/編集/削除は **画面ごとに個別に最後まで実行**し、 結果が **別GET/一覧/詳細/関連画面(生徒側等)** に出るのを確認。

## 5.6 UI到達性・実状態チェック（★必須）

- [ ] 実装済み **全 page ルートを列挙**し、 各々へ **ナビ/リンク/ボタンから到達**できる（孤立/デッドコードゼロ）
- [ ] **実デプロイ先(本番)の実状態**で操作（ローカルseedだけで合格にしない）
- [ ] **0/空**（必須selectの元マスタ0件で詰まないか）・**重複/全半角ゆれ**（同名マスタ2件）・**任意入力の未設定**（締切null 等で後段が失敗しないか）

## 6. バリデーション・サブテーブル

フォームがあるなら、必ずフィールド × ルールをテーブル化:

| # | フィールド | ルール | 入力 | 期待 | 失敗時の実害 |
|---|---|---|---|---|---|
| 1 | email | 必須 | "" | 「メールを入力してください」 | 空送信で 500 |
| 2 | email | 形式 | "abc" | 「メールの形式が不正です」 | 不正データ保存 |
| 3 | password | 最小 8 | "abc1!" | 「8 文字以上にしてください」 | 弱パスワード許容 |
| 4 | password | composition | "abcdefgh" | 「数字 / 記号を含めて」 | 同上 |

クライアント側 / サーバ側の両方で発火するかを別々に確認。

## 7. 境界値チェックリスト

- 最小値 / 1 / 上限 - 1 / 上限ぴったり / 上限 + 1
- 空文字 / null / undefined
- Unicode 多バイト・絵文字・結合文字
- SQL/HTML injection 文字列

## 8. 権限チェックリスト

- 未ログイン
- ログイン済（他人）
- 別ロール（一般 vs 管理者）
- 別テナント
- 期限切れ / revoke 済 token
- **不正トークン（Bearer 任意文字列で 401 を返すか確認）**

## 9. 状態復帰チェックリスト

- リロード
- 別タブで状態変更
- ネットワーク切断 → 復帰
- セッション切れ後の操作

## 10. カバレッジ目標

- P0 は **全数実行が必須**
- P1 は重要分岐をカバー
- P2 は時間が許せば
- 1 機能あたり最低 1 件の **正常系** を必ず含める
- 「失敗時の実害」が **空欄の TC を作らない**（書けないなら TC として弱い → 統合か削除）
